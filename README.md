## Sobre o projeto

O **CLYVO VET** é um sistema de gestão veterinária com banco de dados Oracle.

O projeto armazena informações de:

- Usuários
- Responsáveis
- Veterinários
- Clínicas
- Pets
- Consultas
- Vacinas
- Lembretes
- Sensores
- Leituras
- Logs de erro
- Auditoria

As rotinas em **PL/SQL** (validação, relatórios, tratamento de exceções e auditoria) estão organizadas em **packages**.

Os dados dos pets também são exportados em **JSON** e importados no **MongoDB**, em uma estrutura de banco não relacional de documentos.

## Packages

| Package | Conteúdo | Finalidade |
|---|---|---|
| `pkg_validacao` | `fn_validar_cpf` | Valida o CPF calculando os dígitos verificadores |
| `pkg_consulta` | `fn_consulta_json`, `pr_consulta_pet_json` | Converte as consultas do pet em JSON |
| `pkg_monitoramento` | `pr_relatorio_leituras` | Relatório de atividade por pet, subtotal por espécie e total geral |
| `pkg_auditoria` | `pr_registrar_auditoria` | Grava a auditoria; chamada pela trigger `trg_auditoria_consulta` |
| `pkg_exportacao` | `fn_pet_json`, `pr_exportar_pets` | Monta o documento JSON de cada pet para o MongoDB |

Todas as rotinas possuem tratamento de exceções e registram falhas na tabela `LOG_ERRO`.

O Oracle não permite colocar uma trigger dentro de uma package. Por isso a trigger `trg_auditoria_consulta` continua existindo, mas apenas chama `pkg_auditoria.pr_registrar_auditoria`, que faz a gravação na tabela `AUDITORIA`.

## Correções em relação à Sprint 3

- `LOG_ERRO.id_log_erro` passou a usar `GENERATED BY DEFAULT AS IDENTITY`. Antes os INSERT de log não informavam o id e a gravação falhava.
- `ck_usuario_tipo` passou a aceitar o perfil `ADMIN`, usado pela aplicação Java.
- No `WHEN OTHERS` das procedures, `SQLCODE` e `SQLERRM` passaram a ser guardados em variáveis antes do INSERT no log. O Oracle não permite usá-los diretamente em comandos SQL, o que deixava as procedures inválidas.

## Exportação para o MongoDB

```text
Oracle (pkg_exportacao.pr_exportar_pets)
        ↓
dataset_pets.json
        ↓
MongoDB (banco clyvo_vet, coleção pets)
```

Cada pet vira um documento com o responsável, as consultas, as vacinas e os lembretes **dentro** dele. Assim, todo o histórico do pet é lido em uma única consulta, sem JOIN.

A coleção `pets` possui:

- **Validação** (`$jsonSchema`): campos obrigatórios, tipos e valores aceitos para `sexo`, como as restrições `NOT NULL` e `CHECK` do Oracle.
- **Índices**: por `especie`, por `responsavel.cpf` e por `lembretes.status`.

## Como executar

### Oracle

1. Abrir `docker-entrypoint-initdb.d/sql_challenge.sql` no SQL Developer.
2. Executar o script completo (F5).
3. O bloco `pkg_exportacao.pr_exportar_pets` imprime o JSON dos pets. O conteúdo foi salvo em `dataset_pets.json`.

### MongoDB

1. Executar `mongodb/01_criar_estrutura.js` no mongosh (cria o banco `clyvo_vet` e a coleção `pets` com validação).
2. Importar `dataset_pets.json` conforme `mongodb/02_importacao.txt`.
3. Executar `mongodb/03_indices.js`.
4. Executar `mongodb/04_consultas.js`.
